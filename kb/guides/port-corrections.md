# Corrections found while porting

Index only — each correction is written up in the file it belongs to. These came
out of reimplementing the engine in JavaScript (`web/`, see `web/README.md`),
where a wrong field width or stride shows up immediately as a broken screen or a
desynchronised stream. All were re-derived from the ROM bytes and the assembly,
not from the KB text.

| # | Where | Was | Is | What settled it |

| 1 | [[logo_tile_rows]] | stride 25 (`0x19`), 5 rows | **stride 19 decimal**, 6 rows | The index math at 0x5BC3 computes x→2x→4x→8x→9x→18x→**19x**. With 19 the table ends exactly at 0x4897 (one byte before `entity_update`), the logo tiles run unbroken 0xB0..0xE6, and row 5 comes out as 18 spaces — the blank strip the erase pass needs. Rendering both ways: 19 draws the ZANAC wordmark, 25 draws fragments. |

## Not an error

`shot_power_table`'s first two rows share sprite 0x28, so one power chip
raises LEVEL, the shot speed and the in-flight cap but **not** the number of
streams - the second stream needs a second chip. This looked wrong during the
web port and was briefly patched around; play-testing the original confirmed
the ROM is right and the deviation was reverted. The chain is pinned in
[[shot_power_table]].


`keyboard-input`'s 0xE10C arithmetic (base 4, **+1** up, **−1** down, **−3**
left, **+3** right) is correct as written — it looked inverted until
correction 4 landed, and then matched exactly.


**Fire 3's orbit dips behind the ship, and that is the ROM's own geometry.**
Re-audited end to end after a play-test report that the shield should stay in
front: [[fire-weapon-dispatch]]'s table (init 0x7331 / update 0x735D), the ten
init constants at 0x7331-0x7359, the update at 0x735D-0x73C5 (both 16-bit
accumulators, the Y clamp `[0x38,0xA7]` and the X clamp `[0x48,0xA7]`), the
`vel_dir_table` word order, and the ship's own clamps `[0x1E,0xB8]` /
`[0x28,0xC8]` all match the port. The prescaler was re-checked against the raw
ROM bytes rather than the disassembly listing: `0x4D11-0x4D12 = 29 09` =
`ADD HL,HL` + `ADD HL,BC`, so speed bit 6 really is **x3** (correction 72), and
0xC3 gives x4 * x3 * 3 = **x36**, i.e. 18 px/frame.

The resulting geometry: one direction step per frame (`(IX+0x11)` reloads with
1), so a **16-frame revolution** of radius ~46 px, starting at the **top** -
64 px directly in front - and centred 19 px in front of the ship. It is
therefore in front for roughly three quarters of each turn and passes ~26 px
behind for the rest. Flying low pushes it further forward, because the orbit
follows the *clamped* player Y (max 0xA7) while the ship reaches 0xB8: at the
bottom of the screen only 8 frames in 64 are behind, against 17 at mid-screen.

Its collision gate is `fire_init_table[3] = (200, 0x01)` - bit 0 only, so the
shield hits **airborne** entities and by design passes straight through ground
structures and base segments. A shield-overlapping enemy does register
(`checkEntityCollisions` returns `hitBy: 4`), so blocking works; what it cannot
do is stop anything on the ground layer.

## Also worth knowing

Two behaviours were undocumented rather than wrong, and are now written up where
they belong:

- `map_script_init` seeds `level_row_ctr = trigger − 1` (0x9424), so the first
  step fires the first command instead of skipping it — see
  [[level_script_format]].
- Round 8's script has no `round_jump`; it ends on a `0xFFFF` row trigger, which
  `level_row_ctr` never reaches, and runs on into the ending.

### The one thing the browser will not let the port copy

`title_screen_init` asks for sound event **3** on frame 0 of the cold start, so
on the real machine the title screen and its tune arrive together. A browser
refuses to let a page make any sound before the user has interacted with it —
there is no flag, no permission prompt and no way around it — so on a fresh
load the title runs to a silent output and its tune is never heard. The port
takes this as the cost of being a web page: `web/src/main.js` brings the
`AudioContext` up on the first gesture — keypress, pointer or touch, since a
player who clicks before touching the keyboard would otherwise never get sound
at all — and lets the title screen run regardless, rather than holding the
machine off until the player clicks.
Gating the cold start on the audio was tried and rejected — it buys the
title tune at the price of a black "press any key" screen on every load,
which is the worse trade.
